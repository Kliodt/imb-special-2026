# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Mobile audio guide for the ITMO MEGABATTLE student event (always spelled as one word), styled like a music player (YouTube Music–like). A visitor scans an exhibit QR with the phone camera → the player opens with that exhibit's cover and narration; further exhibits are scanned with the in-player scanner so the ambient bed keeps playing. Vanilla JS + Vite, no framework. All UI text and README are in Russian.

## Commands

```sh
npm run dev       # vite --host (LAN-accessible)
npm run build     # → dist/ (build output, gitignored)
npm run preview
npm run qr        # regenerate public/qr/*.png from public/config.json
```

Production: `docker compose up -d --build` (needs `.env` with `GUIDE_DOMAIN`, see `.env.example`; domain imb-special.ru). `guide` = `nginxinc/nginx-unprivileged` serving `dist/` with `deploy/static.conf`; `public/` is bind-mounted read-only to `/srv/content` and served first, so content edits on the server need no rebuild; `/assets/*` immutable, everything else `no-cache` (ETag); `/health` for the healthcheck. `caddy` terminates TLS (`deploy/Caddyfile`, Let's Encrypt, zstd/gzip incl. wasm); `deploy/nginx.conf` is the host-nginx alternative to the Caddy service.

No automated tests. The live camera scanner needs a secure context (HTTPS or localhost).

## Architecture

- **Tracks are switched only by scanning QR codes** (venue requirement): there is no prev/next logic — the back/next buttons and the cover's QR chip all call `scanner.open()`; closing the scanner keeps the current track playing. Media Session has play/pause handlers only.
- **`public/config.json` is the single source of content**: `siteUrl`, `ambient`, optional `ambientVolume` (0–1, default 0.22 in `player.js`; ignored by iOS, which doesn't let pages set `audio.volume`), and `tracks[]` (`id`, `title`, `artist`, `audio`, `cover`, `qr`, optional `transcript` HTML). The transcript is trusted, valid HTML (mostly `p br b i h1–h4`) inserted as is via `innerHTML` into the full-screen `<dialog id="transcript">`. It is fetched at runtime (top-level `await` in `src/main.js`; controls stay `disabled` until it loads), so it can be edited on the host without a rebuild. Paths are relative to `public/` and used as-is: they resolve against the document URL (the page always lives at its directory URL, `?t=` only changes the query). `scripts/qr.js` reads the same file. Adding a track = drop files into `public/{audio,covers}` + add a config entry + `npm run qr`.
- **Track links/QR payloads** are `<siteUrl>/?t=<id>`, built/parsed only via `src/track-link.js` (DOM-free, also imported by `scripts/qr.js`). `findTrack()` in `src/main.js` accepts them only from `location.origin` or `siteUrl`'s origin; anything else returns -1 (unknown QR must never navigate away). Printed QR codes depend on `id` — don't renumber.
- **`src/player.js`** — `Player`: a single reused `voice` `<audio>` (Safari may block `play()` on a fresh element after a camera scan, so `load()` swaps `src`) plus a looping `bed` (ambient). UI state is derived from the media elements (`playing`, `loading`, `speaking`, `position`, `duration`) and pushed via `onChange`; no custom state machine. Player holds no UI text: it exposes a `Problem` enum and `main.js` maps it to Russian messages. `AbortError` from `play()` means superseded by pause/track switch and is ignored. When narration ends the bed keeps playing (`playing` stays true).
- **`src/scanner.js`** — `Scanner` owns the viewfinder that lives inside the cover square (no dialog, no open/close animation — a clip-path "shutter" was tried and removed as laggy). `open()` is called by `main.js` (QR chip, back, next) and remembers the opener to return focus to; close button, Escape, page hide and an accepted code close it. No hint is shown while aiming; the "not an exhibit code" hint fades out 5 s after it appears (`FOREIGN_FADE`), all status changes go through `#setStatus` so a pending fade is cancelled. Camera: `getUserMedia` → `setTimeout` loop calling `detector.detect(video)`. The detector is the native `BarcodeDetector` when it supports `qr_code` (Chrome on Android), otherwise the `barcode-detector/ponyfill` (ZXing-C++ WASM, ~400 KB gzip), dynamically imported and started while the camera permission prompt is open. The `.wasm` is self-hosted via `import … from 'zxing-wasm/reader/zxing_reader.wasm?url'` + `prepareZXingModule({ overrides: { locateFile } })` — without that it loads from jsDelivr. `zxing-wasm` is intentionally not a direct dependency: `barcode-detector` pins its exact version. `#session` is bumped on every stop so stale camera starts/loops bail out; closing always releases the stream.
- **Progress bar** — straight rail + dot positioned by `--progress` on `#timeline`. The transparent range input must stay on top (`z-index`) — anything decorative above it breaks dragging. Above the passed part `src/waves.js` draws two wave layers on a `<canvas>`. Requirements that shaped it (an SVG/SMIL version was tried and dropped): the waves morph in place between keyframe shapes (not slide); the horizontal scale is fixed in px, so a longer passed part reveals more crests instead of stretching them; the height drops to zero at the dot along a tunable slope (`EDGE`: `width`/`height` in px plus a CSS-style `cubic-bezier` `curve`; linear 30 px over 52 px ≈ 30°, joined to the crest with a soft-min) with a hard left edge. Each layer's shapes are sums of harmonics with shared frequencies, interpolated 1 → 2 → 3 → 1 (`morphMs`). Amplitude rises while narration plays and settles on pause; time is frozen under reduced motion. `timeupdate` is ~4 Hz, so `main.js` runs one `requestAnimationFrame` loop for the dot and the waves while `player.speaking`, while the dot glides and until the waves have settled. The shown progress glides (exponential, `GLIDE_MS`) on jumps larger than `GLIDE_THRESHOLD` — a tap on the line, a track switch, a lock-screen seek — but follows directly during a drag (`dragging` = pointer moved while pressed) and during normal playback; the time label always shows the real position.
- **Play button** — `src/play-icon.js` morphs the icon with SMIL `<animate attributeName="d">` (`beginElement()` with new `from`/`to`): play is an upward triangle split into two halves and rotated 90° by the CSS class `.rotated`, pause is two bars; both paths must keep the same commands and point count. Rounded corners on all control icons come from `.rounded-icon` (fill + same-colour round-joined stroke), so path coordinates are inset by half the stroke width. The icon follows `player.playing` immediately; loading is shown by a spinning ring (`.play::after`), not by replacing the icon.
- **`src/main.js`** — wiring: renders player state into the DOM, prev/next, seek, Media Session, keeps `?t=` in the URL via `replaceState`. On a track change `animateTrackChange()` cross-fades covers (the old one is copied into `#cover-previous` on top and faded out) and fades the titles in, via WAAPI; skipped under reduced motion. Right after start `preloadMedia()` fetches all covers, then all audio (following exhibits first, current last), sequentially into Blob URLs held for the session (`preloaded` map keyed by config path), so scans don't depend on venue Wi-Fi; `showTrack` falls back to the network URL until ready. Media Session artwork always uses the network URL. Nothing persists across reloads.
- **Brand** follows the MEGABATTLE quest teaser (`../quest_teaser`), lifted lighter at the user's request: dark-blue `--bg` with blue corner glows (`body::before`), `--primary` #1f5fff / `--primary-light`; the player card stays the light whitish glass with a light `--border`, glass buttons have no border. Fonts are not the brand's: the user rejected the teaser's Druk Text Wide for the logo and headings — the logo is Arial italic 900, everything else Raleway. `src/decor.js` renders the brand background ported from the teaser's `Background.tsx`: contour-line bundles in two corners and four-point sparkles; sparkles marked `front` sit above the card (`#decor-front`, `pointer-events: none`) because the card covers most of a phone screen.
- **`src/style.css`** — one stylesheet built on tokens in `:root`. Layout rules: one glass surface (`.card`), nothing nested inside it has a border; cover radius = card radius − card padding; the same `--pad` inset on all four screen edges; the cover is always full card width (never shrinks) and `.details` takes the remaining height with `space-evenly`. Short screens (`max-height: 600px`) only tighten the details. Lightning CSS (Vite default) adds `-webkit-` prefixes for `mask`/`backdrop-filter` — don't hand-write them. Font is `@fontsource-variable/raleway` (`'Raleway Variable'`); its default old-style figures are switched to `lining-nums` on `:root` — any element that sets its own `font-variant-numeric` must repeat `lining-nums`.
